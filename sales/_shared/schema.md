# 営業先リストの列定義とスプレッドシートの構成（全クライアント共通）

原本は各クライアントの `sales/clients/<slug>/list/targets.csv`（UTF-8、ヘッダー 1 行、1 案件 1 行）です。
人が見て送付に使うのは、原本から出力する **タブ分けしたスプレッドシート**（Google スプレッドシート / Excel）です。
CSV とスプレッドシートの列順は同じで、`node sales/scripts/targets.mjs` が列・許可値・候補の確度を検証します。

## スプレッドシートのタブ（標準。クライアントごとに変更できる → 末尾「分類設定」）

| タブ | 入る行（プラットフォーム列の値） | 列 |
|------|-------------------------------|----|
| 一覧 | 全件 | 進行管理用の要約列のみ（id・ランク・ステータス・企業名・候補1_確度・問い合わせ先など） |
| ランサーズ | `ランサーズ` | 全列（掲載情報・候補1〜3・提案文 2 種） |
| クラウドワークス | `クラウドワークス` | 全列 |
| 発注ナビ | `発注ナビ` | 全列 |
| Web検索 | `Web検索` | 候補・掲載情報・提案文_プラットフォーム を除いた列（企業は最初から分かっているため） |
| SNS | `SNS` | Web検索 と同じ |
| その他 | `その他マッチング` / `紹介` / `展示会・イベント` / `その他` | 全列 |
| 凡例 | – | 色の意味・編集してよい列・確度の読み方・送付時の注意 |

各タブはランク → ICPスコア → id の順に並びます。見出し行と左 2 列は固定、フィルター付き、`ステータス` `接触チャネル` `ランク` はプルダウンです。

## 列（見出しの色のグループ順）

### 管理（濃いグレー）
| 列 | 意味 |
|----|------|
| id | `T-0001` 形式。クライアント内で一意。ファイル名の接頭にも使う（自動採番） |
| ランク | `A` / `B` / `C` / `除外`（セルの色: A 緑・B 黄・C 灰） |
| ICPスコア | 0〜100。クライアントの `icp.md` の配点 |

### 進行（オレンジ。**人がスプレッドシートで編集してよい列**）
| 列 | 意味 |
|----|------|
| ステータス | `未着手` → `調査中` → `提案作成済` → `送付済` → `返信あり` → `商談中` → `受注` ／ `失注` ／ `保留` ／ `除外` |
| 次アクション | 次にやること 1 行（`送付` / `返信待ち` / `候補の確認（確度 45%）` など） |
| 期限 | 次アクションの期限 `YYYY-MM-DD` |
| 担当者 | 送付する人 |
| 送付日 | 送った日 `YYYY-MM-DD` |
| 接触チャネル | `プラットフォーム応募` / `問い合わせフォーム` / `メール` / `SNS DM` / `LINE` / `電話` / `紹介` / `未定` |
| 企業名 | **送付先として確定した企業**。既定は候補1。特定できなければ `（特定不能）業種＋特徴` |
| 反応メモ | 返信内容・商談メモ（「記録」グループにある） |
| 備考 | 除外理由・注意点（「記録」グループにある） |

### 企業特定（青）
| 列 | 意味 |
|----|------|
| 候補1〜3_企業名 | 掲載情報から Web 検索で推定した企業。確度の高い順 |
| 候補1〜3_確度 | 「この企業が掲載者である」確率（%、整数）。合計 100 以下。残りは「どれでもない」可能性（セルの色: 70 以上 緑・40〜69 黄・40 未満 赤） |
| 候補1〜3_URL | 公式サイトなど、照合に使ったページ |
| 候補1〜3_根拠 | 一致した点（独立した一致点を列挙）と矛盾点 |

### 送付（緑）
| 列 | 意味 |
|----|------|
| 問い合わせ先 | 企業名の会社の公開窓口（問い合わせフォーム URL / 公開メール / 代表電話）。営業 NG 表記があれば空にして備考へ |
| WebサイトURL | 企業名の会社の公式サイト |
| SNS | `ig:@xxx \| x:@yyy \| tiktok:@zzz`（`\|` 区切り） |
| 件名 | メール・フォーム用の件名（30 字以内） |
| 提案文_直接 | 企業名の会社へ直接送る文面。掲載情報にしかない内容（予算・締切・募集文の引用・プラットフォーム名）は含めない |
| 提案文_プラットフォーム | ランサーズ・クラウドワークス・発注ナビ等の応募欄に貼る文面 |

### 掲載情報（グレー。プラットフォーム案件のみ）
| 列 | 意味 |
|----|------|
| 掲載URL | 案件ページの URL（Web検索 / SNS の行では見つけたページ） |
| 案件タイトル / 依頼内容 / 予算 / 納期・期間 / 依頼条件 | 掲載されていたとおりに要約（依頼内容は 200 字以内） |
| 掲載企業情報 | 掲載されている企業の概要（業種・所在地・規模・設立・評価など、見えている範囲そのまま） |

### 企業・評価（紫）
| 列 | 意味 |
|----|------|
| 業種 | クライアントの `config.json` の `industries`（空なら下記の既定リストから） |
| 所在地 / 規模 | `東京都渋谷区` / `個人`・`小規模(〜10名)`・`中小(〜30名)`・`中堅(31〜300名)`・`大手(301名〜)`・`不明` |
| ニーズ要約 | 相手が欲しいこと・課題を 1〜2 文。募集文の言葉をなるべく残す（**必須**） |
| 推奨サービス | クライアントの `config.json` の `services[].id` を `\|` 区切り、主 → 副（**必須**） |
| 属性タグ | 自由タグを `\|` 区切り（下記の推奨値） |

### 記録（グレー）
| 列 | 意味 |
|----|------|
| 反応メモ / 備考 | 上記（人が編集してよい） |
| 登録日 | 追加した日（自動） |
| 更新日時 | 最後に変更した日時 `YYYY-MM-DD HH:MM`（日本時間・自動）。共有先への差分書き出しとチーム通知に使う |
| プラットフォーム | 見つけた場所＝タブの振り分け先（**必須**）: `ランサーズ` / `クラウドワークス` / `発注ナビ` / `その他マッチング` / `Web検索` / `SNS` / `紹介` / `展示会・イベント` / `その他` |
| 調査メモ / 提案文ファイル / 原文ファイル | リポジトリ内のファイルパス（`sales/clients/<slug>/research/T-0001_xxx.md` など） |

必須列: プラットフォーム / 企業名 / ニーズ要約 / 推奨サービス / 接触チャネル / ステータス

## 検証ルール（`targets.mjs validate`）
- 許可値（プラットフォーム・ランク・規模・接触チャネル・ステータス・推奨サービス・業種）
- 候補は 1 から詰めて入れる。確度は 0〜100 の整数、高い順、合計 100 以下
- 日付は `YYYY-MM-DD`、ICPスコアは 0〜100
- 重複: 企業名 / WebサイトURL / 同じ掲載URL の二重登録
- 調査メモ・提案文ファイル・原文ファイルのパスが存在すること

## 既定の業種リスト
`アパレル・雑貨D2C` / `コスメ・美容商材` / `美容サロン` / `飲食` / `ウェルネス・フィットネス` / `クリニック・治療院` / `教育・スクール` / `不動産・住宅` / `ホテル・観光` / `小売・EC` / `製造` / `IT・SaaS` / `BtoBサービス` / `制作会社・代理店` / `士業・コンサル` / `ベンチャー・新規事業` / `その他`

## 属性タグの推奨値
- フェーズ: `立ち上げ` / `成長` / `成熟` / `リブランディング`
- 課題（商材に合わせて増やす）: `SNS属人化` / `集客弱い` / `リピート弱い` / `人手不足` / `業務が属人化` / `制作力不足` / `計測未整備` / `サイトが古い`
- 商流: `EC併設` / `複数店舗` / `店舗型` / `オンライン完結` / `BtoB` / `BtoC`
- 変化: `新店` / `新商品` / `採用強化` / `資金調達` / `周年` / `移転` / `組織変更`
- 案件性質: `単発` / `月額` / `コンペ` / `下請け`

## 分類設定（クライアントの `config.json` の `sheet`）

タブの分け方・独自項目・ステータスはクライアントごとに変えられます。`/sales-hearing` がヒアリングの回答から組み立て、`node sales/scripts/targets.mjs config` で検査、`sheet --demo` でプレビューできます。`sheet` を書かなければ上の標準の分類になります。

```json
"sheet": {
  "tabs": [
    { "name": "製造", "match": { "業種": ["製造"] } },
    { "name": "飲食", "match": { "業種": ["飲食"] } },
    { "name": "A（最優先）", "match": { "ランク": ["A"] }, "color": "B31412" }
  ],
  "overlap": false,
  "fallback_tab": "その他",
  "platforms_extra": ["ココナラ", "Wantedly"],
  "channels_extra": [],
  "statuses": ["未着手", "調査中", "提案作成済", "送付済", "返信あり", "アポ確定", "商談中", "見積提出", "受注", "失注", "保留", "除外"],
  "closed_statuses": ["受注", "失注", "除外"],
  "custom_columns": [
    { "name": "予算帯", "values": ["〜50万", "50〜200万", "200万〜"] },
    { "name": "決裁者", "editable": true },
    { "name": "エリア", "values": ["関東", "関西", "その他"] }
  ],
  "hide_columns": ["属性タグ"],
  "summary_columns": ["id", "ランク", "ステータス", "企業名", "予算帯", "次アクション", "期限"]
}
```

| キー | 意味 |
|------|------|
| `tabs` | 上から順に判定。`match` は `{"列名": ["値", …]}`。複数の列は「かつ」、値の並びは「または」。`推奨サービス`・`属性タグ`・`SNS`・`multi` の独自項目は `\|` 区切りのどれかが当たれば一致。空の値は `""` で指定。`columns` に `"direct"` を書くと候補・掲載情報の列を省く（標準では プラットフォーム が Web検索 / SNS だけのタブは自動で省く） |
| `overlap` | true: 複数のタブの条件に当たる行をすべてのタブに表示。false（既定）: 上のタブに 1 回だけ |
| `fallback_tab` | どのタブにも当たらない行のタブ名（既定「その他」）。`null` にするとそういう行は「一覧」にだけ出る |
| `platforms_extra` / `channels_extra` | プラットフォーム列・接触チャネル列の値を追加 |
| `statuses` | ステータスの一覧（並び順どおりにプルダウンに出る）。**未着手・調査中・提案作成済・送付済・除外は必須**（エージェントが自動で使う） |
| `closed_statuses` | 期限切れ集計から外す完了扱いのステータス |
| `custom_columns` | 独自項目。「企業・評価」と「記録」の間に入る（見出しはティール、`editable: true` ならオレンジ＝人が編集して取り込まれる）。`values` があれば許可値とプルダウン、`multi: true` で `\|` 区切りの複数値、`width` で列幅、`note` で凡例の説明 |
| `hide_columns` | スプレッドシートで表示しない標準の列（原本には残る） |
| `summary_columns` | 「一覧」タブに出す列 |

タブ名は 31 文字以内、`[ ] : * ? / \` は使えず、「一覧」「凡例」は予約済みです。独自項目を追加・削除したら `migrate` で原本を新しい列構成にします（削除した項目の値は備考に移ります）。

## 共有設定（クライアントの `config.json` の `share`）

どこで・誰と・どう共有するかもクライアントごとに決めます。`/sales-hearing` の F 章の回答から組み立て、`node sales/scripts/targets.mjs share` で確認・検査します。

```json
"share": {
  "platform": "notion",
  "update_timing": "each_intake",
  "members": [
    { "name": "佐藤", "role": "送付", "access": "edit", "email": "sato@example.com" },
    { "name": "鈴木", "role": "送付前の確認", "access": "comment", "email": "suzuki@example.com" }
  ],
  "client_access": "view",
  "client_contacts": [ { "name": "山田様", "email": "yamada@client.example" } ],
  "notify": { "channel": "slack", "target": "#sales-acme", "frequency": "daily" },
  "notion": { "parent_page_id": "", "database_id": "", "data_source_id": "", "url": "" },
  "last_push": "",
  "last_notify": ""
}
```

| キー | 値 |
|------|----|
| `platform` | `google_sheets`（タブで分類）／ `notion`（1 社 1 ページ、「分類」列で絞ったビュー）／ `excel`（xlsx を渡す。同時編集は不可）／ `csv`（kintone などへ取り込む） |
| `update_timing` | `each_intake`（取り込みのたび）／ `daily` ／ `weekly` ／ `manual`（依頼時のみ） |
| `members` | 使う人。`access` は `edit` / `comment` / `view` |
| `client_access` / `client_contacts` | クライアント側の見え方（`none` / `view` / `comment` / `edit`）と見る人 |
| `notify` | `channel` は `slack` / `chatwork` / `line_works` / `teams` / `email` / `none`。Slack はコネクタで投稿、それ以外は要約文を渡して人が貼る |
| `notion` | Notion のデータベースの記録（`/sales-list` が書く） |
| `last_push` / `last_notify` | 最後に書き出した・通知した日時（`targets.mjs pushed` が書く） |

### 共有先ごとの違い
| 共有先 | 分類の見せ方 | 人の編集の取り込み | 同時編集 |
|--------|-------------|--------------------|----------|
| Google スプレッドシート | タブ | シートを読んで `pull` | ○ |
| Notion | 「分類」列で絞ったビュー。提案文・候補・掲載情報は各ページの本文 | データベースを読んで `pull` | ○ |
| Excel | タブ | 編集済みファイルを `xlsx_rows.py` → `pull` | × |
| CSV | 末尾の「分類」列 | 取り込み先から書き出した CSV を `pull` | ツールによる |

- Notion ページの id は `list/share_map.json` に記録します（チームで共有するのでコミットする）。
- 書き出し用のデータは `targets.mjs payload --format notion|google_sheets|rows`、Notion のプロパティ定義は `notion-schema` で出力します。

## スプレッドシートの記録（クライアントの `config.json` の `spreadsheet`）
`folder_id` / `current_id` / `current_url` / `previous_ids`。`/sales-list` が出力のたびに更新します。手で編集する必要はありません。
