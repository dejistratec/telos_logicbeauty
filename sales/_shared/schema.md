# 営業先リストの列定義とスプレッドシートの構成（全クライアント共通）

原本は各クライアントの `sales/clients/<slug>/list/targets.csv`（UTF-8、ヘッダー 1 行、1 案件 1 行）です。
人が見て送付に使うのは、原本から出力する **タブ分けしたスプレッドシート**（Google スプレッドシート / Excel）です。
CSV とスプレッドシートの列順は同じで、`node sales/scripts/targets.mjs` が列・許可値・候補の確度を検証します。

## スプレッドシートのタブ

| タブ | 入る行（プラットフォーム列の値） | 列 |
|------|-------------------------------|----|
| 一覧 | 全件 | 進行管理用の要約列のみ（id・ランク・ステータス・企業名・候補1_確度・問い合わせ先など） |
| ランサーズ | `ランサーズ` | 全列（掲載情報・候補1〜3・提案文 2 種） |
| クラウドワークス | `クラウドワークス` | 全列 |
| 発注ナビ | `発注ナビ` | 全列 |
| Web検索 | `Web検索` | 候補・掲載情報・提案文_プラットフォーム を除いた列（企業は最初から分かっているため） |
| SNS | `SNS` | Web検索 と同じ |
| その他 | `その他マッチング` / `紹介` / `展示会・イベント` / `その他` | 全列 |
| 凡例 | – | 色の意味・編集してよい列・確度の読み方・送付時の注意 |

各タブはランク → ICPスコア → id の順に並びます。見出し行と左 2 列は固定、フィルター付き、`ステータス` `接触チャネル` `ランク` はプルダウンです。

## 列（見出しの色のグループ順）

### 管理（濃いグレー）
| 列 | 意味 |
|----|------|
| id | `T-0001` 形式。クライアント内で一意。ファイル名の接頭にも使う（自動採番） |
| ランク | `A` / `B` / `C` / `除外`（セルの色: A 緑・B 黄・C 灰） |
| ICPスコア | 0〜100。クライアントの `icp.md` の配点 |

### 進行（オレンジ。**人がスプレッドシートで編集してよい列**）
| 列 | 意味 |
|----|------|
| ステータス | `未着手` → `調査中` → `提案作成済` → `送付済` → `返信あり` → `商談中` → `受注` ／ `失注` ／ `保留` ／ `除外` |
| 次アクション | 次にやること 1 行（`送付` / `返信待ち` / `候補の確認（確度 45%）` など） |
| 期限 | 次アクションの期限 `YYYY-MM-DD` |
| 担当者 | 送付する人 |
| 送付日 | 送った日 `YYYY-MM-DD` |
| 接触チャネル | `プラットフォーム応募` / `問い合わせフォーム` / `メール` / `SNS DM` / `LINE` / `電話` / `紹介` / `未定` |
| 企業名 | **送付先として確定した企業**。既定は候補1。特定できなければ `（特定不能）業種＋特徴` |
| 反応メモ | 返信内容・商談メモ（「記録」グループにある） |
| 備考 | 除外理由・注意点（「記録」グループにある） |

### 企業特定（青）
| 列 | 意味 |
|----|------|
| 候補1〜3_企業名 | 掲載情報から Web 検索で推定した企業。確度の高い順 |
| 候補1〜3_確度 | 「この企業が掲載者である」確率（%、整数）。合計 100 以下。残りは「どれでもない」可能性（セルの色: 70 以上 緑・40〜69 黄・40 未満 赤） |
| 候補1〜3_URL | 公式サイトなど、照合に使ったページ |
| 候補1〜3_根拠 | 一致した点（独立した一致点を列挙）と矛盾点 |

### 送付（緑）
| 列 | 意味 |
|----|------|
| 問い合わせ先 | 企業名の会社の公開窓口（問い合わせフォーム URL / 公開メール / 代表電話）。営業 NG 表記があれば空にして備考へ |
| WebサイトURL | 企業名の会社の公式サイト |
| SNS | `ig:@xxx \| x:@yyy \| tiktok:@zzz`（`\|` 区切り） |
| 件名 | メール・フォーム用の件名（30 字以内） |
| 提案文_直接 | 企業名の会社へ直接送る文面。掲載情報にしかない内容（予算・締切・募集文の引用・プラットフォーム名）は含めない |
| 提案文_プラットフォーム | ランサーズ・クラウドワークス・発注ナビ等の応募欄に貼る文面 |

### 掲載情報（グレー。プラットフォーム案件のみ）
| 列 | 意味 |
|----|------|
| 掲載URL | 案件ページの URL（Web検索 / SNS の行では見つけたページ） |
| 案件タイトル / 依頼内容 / 予算 / 納期・期間 / 依頼条件 | 掲載されていたとおりに要約（依頼内容は 200 字以内） |
| 掲載企業情報 | 掲載されている企業の概要（業種・所在地・規模・設立・評価など、見えている範囲そのまま） |

### 企業・評価（紫）
| 列 | 意味 |
|----|------|
| 業種 | クライアントの `config.json` の `industries`（空なら下記の既定リストから） |
| 所在地 / 規模 | `東京都渋谷区` / `個人`・`小規模(〜10名)`・`中小(〜30名)`・`中堅(31〜300名)`・`大手(301名〜)`・`不明` |
| ニーズ要約 | 相手が欲しいこと・課題を 1〜2 文。募集文の言葉をなるべく残す（**必須**） |
| 推奨サービス | クライアントの `config.json` の `services[].id` を `\|` 区切り、主 → 副（**必須**） |
| 属性タグ | 自由タグを `\|` 区切り（下記の推奨値） |

### 記録（グレー）
| 列 | 意味 |
|----|------|
| 反応メモ / 備考 | 上記（人が編集してよい） |
| 登録日 | 追加した日（自動） |
| プラットフォーム | 見つけた場所＝タブの振り分け先（**必須**）: `ランサーズ` / `クラウドワークス` / `発注ナビ` / `その他マッチング` / `Web検索` / `SNS` / `紹介` / `展示会・イベント` / `その他` |
| 調査メモ / 提案文ファイル / 原文ファイル | リポジトリ内のファイルパス（`sales/clients/<slug>/research/T-0001_xxx.md` など） |

必須列: プラットフォーム / 企業名 / ニーズ要約 / 推奨サービス / 接触チャネル / ステータス

## 検証ルール（`targets.mjs validate`）
- 許可値（プラットフォーム・ランク・規模・接触チャネル・ステータス・推奨サービス・業種）
- 候補は 1 から詰めて入れる。確度は 0〜100 の整数、高い順、合計 100 以下
- 日付は `YYYY-MM-DD`、ICPスコアは 0〜100
- 重複: 企業名 / WebサイトURL / 同じ掲載URL の二重登録
- 調査メモ・提案文ファイル・原文ファイルのパスが存在すること

## 既定の業種リスト
`アパレル・雑貨D2C` / `コスメ・美容商材` / `美容サロン` / `飲食` / `ウェルネス・フィットネス` / `クリニック・治療院` / `教育・スクール` / `不動産・住宅` / `ホテル・観光` / `小売・EC` / `製造` / `IT・SaaS` / `BtoBサービス` / `制作会社・代理店` / `士業・コンサル` / `ベンチャー・新規事業` / `その他`

## 属性タグの推奨値
- フェーズ: `立ち上げ` / `成長` / `成熟` / `リブランディング`
- 課題（商材に合わせて増やす）: `SNS属人化` / `集客弱い` / `リピート弱い` / `人手不足` / `業務が属人化` / `制作力不足` / `計測未整備` / `サイトが古い`
- 商流: `EC併設` / `複数店舗` / `店舗型` / `オンライン完結` / `BtoB` / `BtoC`
- 変化: `新店` / `新商品` / `採用強化` / `資金調達` / `周年` / `移転` / `組織変更`
- 案件性質: `単発` / `月額` / `コンペ` / `下請け`

## スプレッドシートの出力先（クライアントの `config.json` の `spreadsheet`）
```json
"spreadsheet": {
  "auto_publish": true,
  "folder_id": "",
  "current_id": "",
  "current_url": "",
  "previous_ids": []
}
```
`/sales-list` が出力のたびに更新します。手で編集する必要はありません。
