# 営業代行オペレーション（`sales/`）

**営業代行**のための専用フォルダです。クライアント（＝売る商材を持つ企業）を `sales/clients/<slug>/` に登録すると、
そのクライアントの商材を理解した上で、次の流れを半自動化します。

```
 クライアント（営業する側の企業）
   │  サイト・資料 → /sales-setup（商材の整理）
   │  ヒアリング   → /sales-hearing（商材の確認・営業先の基準・リストの分け方・名義）
   ▼
 分類設定（タブ・独自項目・ステータス）＋ 商材プロファイル ＋ 選定基準 ＋ 営業文の設定
   │
 ランサーズ / クラウドワークス / 発注ナビ の案件ページ        Web検索・SNS で見つけた企業
   （企業概要・依頼内容・条件）をコピペ or スクショ                  │
                 │                                                 │
                 ▼                                                 ▼
          /sales-intake ─────────────────────────────── /sales-prospect
                 │ ① 原文を保存し、掲載情報を抜き出す
                 │ ② Web 検索で企業を特定 → 候補を確度の高い順に 3 つ
                 │ ③ 送付先企業の公開情報を調査（問い合わせ先・営業 NG 表記・現状）
                 │ ④ ICP スコアとランク
                 │ ⑤ 提案文を必ず作る（直接連絡用＋プラットフォーム応募用）
                 ▼
   スプレッドシート（タブはヒアリングで決めた分類。標準は 一覧 / ランサーズ / クラウドワークス / 発注ナビ / Web検索 / SNS / その他 / 凡例）
                 │
                 ▼
   人がシートを見て送付 → ステータス・送付日をシートに記入 → 次回の更新で原本に取り込み
```

人が行うのは **「クライアントにヒアリングする（シートを送るか、聞いた内容を伝える）」「案件情報を貼る・スクショを添付する」「シートを見て送る」** だけ、を目指しています。

## 全体フロー

| # | 工程 | 自動化度 | スキル | 出力先（`<C>` = `sales/clients/<slug>`） |
|---|------|----------|--------|-------------------------------------------|
| 0 | **クライアント（商材）の理解** — サイト・資料から商材・価格・実績・ICP の下書き | 半自動 | `/sales-setup` | `<C>/offering.md` `icp.md` `config.json` `outreach.md` |
| 0' | **ヒアリング** — シートを作って先方に記入してもらう／チャットで聞く／議事録を取り込む → 分類（タブ・独自項目・ステータス）と各設定に反映、プレビューを作る | 半自動（回答は先方、反映は自動） | `/sales-hearing` | `<C>/hearing/`, `<C>/config.json` の `sheet` ほか |
| 1 | 案件の取り込み（コピペ・スクショ・URL）と掲載情報の抜き出し | 自動 | `/sales-intake` | `<C>/intake/` |
| 2 | 企業特定（候補 3 つ・確度 % 付き） | 自動（確度 50% 未満は人が確認） | `/sales-intake` | `<C>/research/`, シートの「候補1〜3」 |
| 3 | 送付先企業の調査・ICP スコア・ランク | 自動 | `/sales-intake` / `/sales-qualify` | `<C>/research/`, シートの「ランク」 |
| 4 | 提案文（直接連絡用＋プラットフォーム応募用、相手の文体・ニーズに合わせる） | 自動（最終確認は人） | `/sales-intake` / `/sales-proposal` | `<C>/proposals/`, シートの「提案文_直接」「提案文_プラットフォーム」 |
| 5 | Web検索・SNS からの営業先発掘 | 半自動 | `/sales-prospect` | シートの「Web検索」「SNS」タブ |
| 6 | スプレッドシートの出力・人の編集の取り込み・集計 | 自動 | `/sales-list` | Google スプレッドシート / `<C>/list/targets.xlsx` |
| 7 | 送付 | **人** | – | – |

## 使い方（最短）

```text
# 0. クライアントを登録して商材を理解させる（最初に 1 回）
/sales-setup acme-inc https://acme.example.jp/ （料金表や資料があれば貼る・添付する）

# 0'. ヒアリング（シートを作る → 先方が記入 → 反映。打ち合わせメモの貼り付けでも可）
/sales-hearing シート作成
/sales-hearing 反映 https://docs.google.com/document/d/…
/sales-hearing 反映 <打ち合わせのメモや議事録を貼り付け>

# 1. 案件ページの内容をそのまま貼る（複数件まとめても可）／スクリーンショットを添付する
/sales-intake <ランサーズや発注ナビの企業概要・依頼内容・条件を貼り付け>

# 2. Web・SNS から営業先を探してもらう
/sales-prospect 関東の製造業で、採用ページが古く求人を複数出している 30〜100 名規模 10 社

# 3. 送付先を候補2に変えて提案文を作り直す
/sales-proposal T-0003 候補2

# 4. スプレッドシートで記入したステータスを取り込んで、シートを更新
/sales-list スプレッドシートを更新

# 5. 集計・クライアント切替
/sales-list 集計
/sales-list 切替 acme-inc
```

複数クライアントを並行するときは各コマンドに `--client <slug>` を付けるか、`/sales-list 切替 <slug>` で既定を変えます。
スキルを使わずに手で操作する場合は `node sales/scripts/targets.mjs --help`。

## スプレッドシート

- **タブ**: ヒアリングで決めた分類（業種別・商材別・地域別・優先度別など）。決めていなければ標準の 一覧／ランサーズ／クラウドワークス／発注ナビ／Web検索／SNS／その他／凡例。分類・独自項目・ステータスは `config.json` の `sheet` にあり、あとから何度でも変えられます（書き方は `_shared/schema.md`）。
- **見出しの色**: 管理（濃いグレー）・**進行（オレンジ＝人が編集してよい列）**・企業特定（青）・送付（緑）・掲載情報（グレー）・企業・評価（紫）・記録。
- **候補1〜3_確度**: 緑 70% 以上・黄 40〜69%・赤 40% 未満。赤は送る前に人が確認する。
- **送付**: 「提案文_直接」は特定した企業への問い合わせフォーム・メール・SNS DM 用、「提案文_プラットフォーム」は応募欄用。複数行のセルは、セル内をダブルクリックして全選択 → コピーすると余計な `"` が付きません。
- **人の編集の取り込み**: オレンジの列（ステータス・次アクション・期限・担当者・送付日・接触チャネル・企業名・反応メモ・備考）だけが、次回の更新時に原本へ取り込まれます。他の列は上書きされます。
- **出力の経路**（`/sales-list` が自動で選ぶ）:
  | 使えるコネクタ | 動き |
  |---------------|------|
  | Google Sheets コネクタ | 同じスプレッドシートに追記・更新。**リンクが変わらない（推奨）** |
  | Google Drive コネクタのみ | 出力のたびに新しいスプレッドシートを作り、古い方の名前に（旧）を付ける |
  | なし | `<C>/list/targets.xlsx` を渡す（Excel で開く／Google スプレッドシートにインポート） |

```
sales/
├── README.md                    このファイル
├── _shared/                     全クライアント共通
│   ├── agency.md                代行会社（自社）のプロファイル・署名【要記入】
│   ├── outreach_rules.md        営業文の共通ルール（直接連絡用／プラットフォーム用・文字数・文体・法令表記）
│   └── schema.md                列定義・タブ構成・検証ルール
├── _templates/
│   ├── client/                  init が複製するクライアント用テンプレ（config.json / offering.md / icp.md / outreach.md）
│   ├── hearing.json             ヒアリングの質問（28 問。各問の反映先つき）
│   ├── intake.md  research.md  proposal.md
├── clients/
│   ├── ACTIVE                   既定クライアントの slug
│   ├── telos/                   記入済みサンプル（このリポジトリのサイトから作成）
│   └── <slug>/
│       ├── config.json          名称・商材 id・業種リスト・分類設定（sheet）・スプレッドシートの出力先
│       ├── hearing/             ヒアリングシート（sheet.md）と回答（answers.json / answers.md）
│       ├── offering.md          商材の理解（価値・価格・範囲・実績・差別化・反論・NG 表現）
│       ├── icp.md               理想顧客像・シグナル・スコア配点・除外
│       ├── outreach.md          名義・署名・CTA・商材別「最初に起きること」・勝ちパターン
│       ├── intake/              取り込んだ原文（スクショは書き起こし）と掲載情報
│       ├── research/            案件ごとの調査メモ（候補 3 つの根拠・観察・スコア内訳）
│       ├── proposals/           案件ごとの提案文（直接用・プラットフォーム用・2 通目の骨子）
│       └── list/targets.csv     営業先リストの原本（targets.xlsx はここから出力）
└── scripts/targets.mjs          クライアント管理・分類設定の検査・ヒアリングシート出力・リストの追加/更新/取り込み/検証/集計・xlsx 出力（依存なし）
```

## 守るべきルール（必読）

1. **プラットフォーム案件への直接連絡は運用者の判断**
   この仕組みは、ランサーズ・クラウドワークス・発注ナビ等で見つけた案件について、特定した企業へ直接送る文面も用意します。直接送るかどうかは送付者が決めます。
   各プラットフォームの規約はサイト外での直接取引・直接連絡を禁止・制限しており、アカウント停止や違約金の対象になり得ます。そのリスクは運用者とクライアントが負います。判断に迷う案件は「提案文_プラットフォーム」を使ってください。
2. **直接連絡用の文面には、掲載情報にしかない内容を書かない**
   予算・締切・募集文の引用・プラットフォーム名は入れません。特定が外れていた場合に別の会社の非公開情報を漏らさないためです（スキルが自動で守ります）。
3. **候補の確度を確認してから送る**
   候補1_確度が 50% 未満の行は「候補の確認」が次アクションになります。企業名と送付先が合っているかを人が確かめてから送ってください。
4. **個人は特定しない**
   掲載者が個人（個人の依頼主）と思われる案件は特定しません。担当者個人の連絡先も探しません。記録するのは会社の公開窓口だけです。
5. **名義を曖昧にしない**
   クライアント名義か代行会社名義かを `outreach.md` で決め、文面の冒頭で立場を明示します。第三者を装わず、事実と違う連絡理由（紹介を受けた等）を書きません。
6. **メール・フォーム営業は特定電子メール法に従う**
   送信者の名称・住所・連絡先と受信拒否の方法を明記します。「営業目的のお問い合わせはご遠慮ください」と明示しているサイトには送りません。
7. **SNS の情報は公開情報のみ**
   ログインが必要な情報の取得、スクレイピング、自動フォロー・自動 DM は行いません。
8. **実績・数値・価格は各クライアントの `offering.md` にあるものだけ**を使います。業法上の表現規制があれば `offering.md` §6 に書いて守ります。
9. **クライアント間でデータを混ぜない。**

## 保守

- クライアントの商材・価格が変わったら `<C>/offering.md` と `outreach.md` §4 を更新する。
- 狙う業種や予算帯を変えたら `<C>/icp.md` を更新し、`/sales-qualify all` で再ランク付けする。
- タブの分け方や独自項目を変えたら `node sales/scripts/targets.mjs config` で確認し、`migrate` → `/sales-list スプレッドシートを更新`。
- 反応が良かった文面の特徴は `<C>/outreach.md` §7「勝ちパターン」に追記する。
- `<C>/list/targets.xlsx` と `targets.export.csv` は出力ファイルで、Git には含めません。
- 代行会社名義で送る場合は、先に `sales/_shared/agency.md` の `【要記入】` を埋める。
