# 営業代行オペレーション（`sales/`）

**営業代行**のための専用フォルダです。クライアント（＝売る商材を持つ企業）を `sales/clients/<slug>/` に登録すると、
そのクライアントの商材を理解した上で、**営業先の発掘・特定・調査 → 選定（スコアリング）→ 営業文・提案文の作成 → 送付 → 追跡**
のうち「送付」以外を半自動化できます。クライアントを切り替えれば、どの企業の営業代行にも同じ流れで使えます。

Claude Code のスキル（`.claude/skills/sales-*`）がこのフォルダを読み書きします。
人が行うのは **「クライアント資料を渡す」「原文を貼る」「ランクと文面を確認する」「送る」** だけ、を目指しています。

---

## 全体フロー

| # | 工程 | 自動化度 | スキル | 出力先（`<C>` = `sales/clients/<slug>`） |
|---|------|----------|--------|-------------------------------------------|
| 0 | **クライアント（商材）の理解** — サイト・資料から商材・価格・実績・ICP を整理 | 半自動（価格・実績・名義は人が確認） | `/sales-setup` | `<C>/offering.md` `icp.md` `config.json` `outreach.md` |
| 1 | 営業先の発掘（セグメント指定で候補を探す） | 半自動 | `/sales-prospect` | `<C>/intake/`, `<C>/list/targets.csv` |
| 2 | 取り込み・企業特定（発注なび / ランサーズ等の原文を貼る） | 半自動 | `/sales-intake` | `<C>/intake/`, `<C>/research/` |
| 3 | 調査（Web / SNS / 公開情報 → 現状・課題・文体） | 自動 | `/sales-intake` 内 | `<C>/research/<id>_<slug>.md` |
| 4 | 選定・スコアリング（ICP 照合 → A/B/C ランク） | 自動 | `/sales-qualify` | `<C>/list/targets.csv` |
| 5 | 営業文・提案文の生成（相手の文体・ニーズ・チャネルに適応） | 自動（最終確認は人） | `/sales-proposal` | `<C>/proposals/<id>_<slug>.md` |
| 6 | 送付 | **手動** | – | – |
| 7 | リスト管理・分類・集計・スプレッドシート出力・クライアント切替 | 自動 | `/sales-list` | `<C>/list/` |

```
 クライアントの資料・サイト ──▶ /sales-setup ──▶ <C>/offering.md（商材）・icp.md（誰を狙う）・outreach.md（名義・署名・CTA）
                                                       │ 以降すべての工程がこれを根拠にする
  発注なび / ランサーズ / Web / SNS / 紹介              ▼
                 │  コピペ or URL              /sales-prospect（候補を探す）
                 ▼                                     │
        /sales-intake ──▶ <C>/intake/（原文） ◀────────┘
                 ├─▶ 企業特定（Web 検索・照合・確度付き）
                 ├─▶ 公開情報調査（商材に関係する領域を中心に）
                 ├─▶ <C>/research/<id>_<slug>.md（現状・課題仮説・文体・切り口・スコア内訳）
                 └─▶ <C>/list/targets.csv に 1 行追加（ICP スコア・ランク）
                                 │
        /sales-qualify ──────────┤  再スコア・優先順位付け
                                 ▼
        /sales-proposal ──▶ <C>/proposals/<id>_<slug>.md（チャネル別の文面・2 通目の骨子）
                                 │
                            人が確認して送付 ──▶ /sales-list で状態更新・集計・出力
```

---

## 使い方（最短）

```text
# 0. クライアントを登録して商材を理解させる（最初に 1 回）
/sales-setup acme-inc https://acme.example.jp/ （料金表や資料があれば貼る・添付する）

# 1. 発注なび / ランサーズ の案件文をそのまま貼る
/sales-intake <案件文をここに貼り付け>

# 2. 候補を探してもらう
/sales-prospect 関東の製造業で、採用ページが古く求人を複数出している 30〜100 名規模 10 社

# 3. 優先順位を付け直す（ICP を変えた時など）
/sales-qualify all

# 4. 提案文を作る（id は targets.csv の id 列）
/sales-proposal T-0001
/sales-proposal T-0001 メール用に

# 5. 集計・検証・出力・クライアント切替
/sales-list 集計
/sales-list Google スプレッドシートに出力
/sales-list クライアント一覧
/sales-list 切替 acme-inc
```

複数クライアントを並行するときは、各コマンドに `--client <slug>` を付けるか、`/sales-list 切替 <slug>` で既定を変えます。
スキルを使わずに手で操作する場合は `node sales/scripts/targets.mjs --help`。

## フォルダ構成

```
sales/
├── README.md                    このファイル
├── _shared/                     全クライアント共通
│   ├── agency.md                代行会社（自社）のプロファイル・署名【要記入】
│   ├── outreach_rules.md        営業文の共通ルール（骨格・チャネル別文字数・文体適応・法令表記）
│   └── schema.md                targets.csv の列定義・分類の値
├── _templates/
│   ├── client/                  init が複製するクライアント用テンプレ（config.json / offering.md / icp.md / outreach.md）
│   ├── intake.md  research.md  proposal.md
├── clients/
│   ├── ACTIVE                   既定クライアントの slug（use で設定。無ければ --client 必須）
│   ├── telos/                   記入済みサンプル（このリポジトリのサイトから作成）
│   └── <slug>/                  クライアントごと
│       ├── config.json          名称・商材 id（推奨サービス列の許可値）・業種リスト・スプレッドシート URL
│       ├── offering.md          商材の理解（価値・価格・範囲・実績・差別化・反論・NG 表現）
│       ├── icp.md               理想顧客像・シグナル・スコア配点・除外
│       ├── outreach.md          名義・署名・CTA・商材別「最初に起きること」・勝ちパターン
│       ├── intake/              取り込んだ原文
│       ├── research/            営業先ごとの調査メモ
│       ├── proposals/           営業先ごとの営業文・提案文
│       └── list/targets.csv     営業先リスト（スプレッドシートの原本）
└── scripts/targets.mjs          クライアント管理＋リストの追加・更新・検証・集計・Excel/Sheets 向け出力
```

ファイル名は `T-0001_apparel-d2c-a.md` のように **`<id>_<英数字スラッグ>`**（id は `targets.csv` と一致、クライアント内で一意）。

## 守るべきルール（必読）

1. **プラットフォーム経由の案件は、プラットフォーム経由で提案する**
   ランサーズ・発注なび・クラウドワークス等は、サイト外での直接取引や直接連絡を規約で禁止・制限しています。
   `/sales-intake` が企業を特定するのは「相手を深く理解して、プラットフォーム上の提案文を相手に合わせて書くため」です。
   直接連絡先を探して外部から営業する目的には使いません。スクリプトは `接触チャネル = プラットフォーム応募` 以外を検証エラーにします。
   直接営業する企業は `/sales-prospect` で Web / SNS など公開チャネルから独立に見つけたものに限ります。
2. **名義を曖昧にしない**
   クライアント名義か代行会社名義かを `outreach.md` で決め、文面の冒頭で立場を明示する。第三者を装わない。
3. **メール・フォーム営業は特定電子メール法に従う**
   送信者の名称・住所・連絡先を明記し、受信拒否（オプトアウト）の導線を入れる。
   「営業目的のメールお断り」「営業のお問い合わせはご遠慮ください」と明示しているサイトには送らない。
4. **SNS の情報は公開情報のみ**
   ログインが必要な情報の取得、スクレイピング、自動フォロー・自動 DM は行わない。
5. **実績・数値・価格は各クライアントの `offering.md` にあるものだけを使う**（誇張・創作をしない）。業法上の表現規制があれば `offering.md` §6 に書いて守る。
6. **個人情報は必要最小限**。担当者個人のメールや電話は、規約上・法令上問題がない場合のみ記録し、不要になれば削除する。
7. **推測は推測と書く**。企業特定の確度（高/中/低/特定不能）、課題仮説、文体の読み取りは必ず根拠を添える。
8. **クライアント間でデータを混ぜない**。報告・ファイル・リストは常に対象クライアントを明示する。

---

## 保守

- クライアントの商材・価格が変わったら `<C>/offering.md` と `outreach.md` §4 を更新する。
- 狙う業種や予算帯を変えたら `<C>/icp.md` を更新し、`/sales-qualify all` で再ランク付けする。
- 文面の型が固まってきたら `<C>/outreach.md` §7「勝ちパターン」に追記する。
- `<C>/list/targets.export.csv` は Excel 用の書き出し（BOM 付き）で、Git には含めません。
- 代行会社名義で送る場合は、先に `sales/_shared/agency.md` の `【要記入】` を埋める。
