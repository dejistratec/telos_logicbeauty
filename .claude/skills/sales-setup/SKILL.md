# /sales-setup — クライアント（売る商材）の登録と理解

入力: `$ARGUMENTS`

これは全工程の起点です。ここで作る `offering.md` と `icp.md` の質が、以降の選定・提案文の質を決めます。

## 手順

### 1. クライアントを作る（または選ぶ）
- `node sales/scripts/targets.mjs clients` で既存を確認。
- 新規なら `node sales/scripts/targets.mjs init <slug> --name "<正式名称>" --use`。slug は英小文字・数字・ハイフン（例: `acme-inc`）。社名しか無ければ slug はローマ字で作り、そう述べる。
- 既存を既定にするだけなら `node sales/scripts/targets.mjs use <slug>` で終了。
- 以降 `<C>` = `sales/clients/<slug>`。

### 2. 材料を集める（公開情報＋渡された資料）
| 材料 | 手段 | 取るもの |
|------|------|---------|
| 公式サイト（トップ・サービス・料金・事例・会社概要） | WebFetch | 商材一覧、価格、範囲、事例と数値、会社規模、問い合わせ導線、表現のトーン |
| 渡された資料・貼り付け文 | Read | 価格表、提供範囲、NG 事項、ターゲット、実績 |
| 競合・業界の一般情報 | WebSearch（2〜3 回） | 業界の相場感・規制（医療・金融・不動産・士業などの広告表現規制） |
| 既存顧客・事例ページ | WebFetch | 誰に売れているか（業種・規模）→ ICP の初版 |

取れない項目は `【要確認】` を付けて空欄で残す。**価格・実績・導入社数を推測で埋めない。**

### 3. `config.json` を埋める
- `services`: 商材ごとに `{ "id": "英小文字-id", "label": "表示名" }`。id は短く安定した名前（例: `seo`, `web-production`, `recruit-ads`）。
- `industries`: 営業先の業種を絞りたい場合だけ入れる（空なら `sales/_shared/schema.md` の既定リストで自由入力）。
- `name` は正式表記に直す。

### 4. `offering.md` を書く（テンプレの見出しを全部残す）
- §2 商材一覧の見出しを `config.json` の id と一致させる。
- 価格は表記（税抜/税込、〜、/月、最低金額、別途費用）をそのまま転記し、出典を §0 に書く。
- §3 実績は公開可能な表記で。匿名指定・推測禁止。
- §5 反論と返しは、サイトの FAQ・事例から作れる範囲で。無ければ業界の一般的な反論を入れ `【仮説】`。
- §6 使わない表現に、業法・ガイドライン上の注意を入れる（該当業界のみ）。

### 5. `icp.md` を書く（初版は仮説でよい）
- §1 コアは「向いている相手」「事例の業種・規模」「価格に対して妥当な予算を持てる規模」から導出し、`【仮説】` を付ける。
- §2 シグナルは、**この商材が売れる相手がサイト・SNS・募集文で何を言っているか**を具体語で書く（例: 「問い合わせが減った」「採用が追いつかない」「現行システムが古い」）。
- 配点（§3）は共通の 5 観点のまま。重みを変えたい場合は理由を書いて変える。

### 6. `outreach.md` を書く
- §1 名義（クライアント名義／代行会社名義）は**ユーザーに確認が要る**項目。既定はクライアント名義で `【要確認】` を残す。
- §4 商材別「最初に起きること」は `offering.md` の進め方から作る。価格の書き方も転記。
- §5 チャネルの優先順位は、商材の性質（BtoB／BtoC、単価、意思決定者）から仮説で。
- 代行会社名義の可能性があれば `sales/_shared/agency.md` の `【要記入】` が残っていることをユーザーに伝える。

### 7. スプレッドシートの出力先を決める
- Google のツールを確認する（ToolSearch で `google sheets` `google drive`）。Google Sheets コネクタがあれば同じシートを直接更新でき、リンクが変わらない。Drive コネクタだけなら出力のたびに新しいシートになる。どちらも無ければ xlsx を渡す。
- Sheets コネクタが無い場合は、「Google Sheets コネクタを追加すると、同じスプレッドシートに追記・更新できてリンクが変わらない」と 1 行伝える。
- `config.json` の `spreadsheet.auto_publish` は既定で true。ユーザーがスプレッドシートを使わないなら false にする。

### 8. 検証と報告
- `node sales/scripts/targets.mjs validate`（0 件でも config の警告が消えることを確認）。
- チャットには: 作ったファイル一覧 ／ 商材 id 一覧 ／ ICP コアの 1 行要約 ／ **`【要確認】` と `【仮説】` の一覧**（ユーザーが埋めるべき箇所。価格・名義・実績が最優先）／ 次の一手（`/sales-intake` か `/sales-prospect`）。

## 禁止事項
- 価格・実績・導入社数・顧客名を推測で書くこと（空欄＋`【要確認】` にする）。
- 既存クライアントの `offering.md` を、ユーザーの指示なく上書きすること（更新は差分を示してから）。
- `sales/_shared/` の共通ルールをクライアント都合で書き換えること（固有の設定は `outreach.md` へ）。
