# /sales-proposal — 営業文・提案文の生成（直接連絡用＋プラットフォーム応募用）

入力: `$ARGUMENTS`

## クライアントの決め方
`/sales-intake` と同じ。以降 `<C>` = `sales/clients/<slug>`、`T` = `node sales/scripts/targets.mjs`。

## 先に読むもの（毎回）
1. `T get <id>` と `<C>/research/<id>_*.md`（無ければ先に `/sales-intake`）
2. `<C>/offering.md`（価格・範囲・実績・反論・NG 表現）
3. `sales/_shared/outreach_rules.md` → `<C>/outreach.md`（名義・署名・CTA・商材別「最初に起きること」・勝ちパターン）
4. 名義が代行会社なら `sales/_shared/agency.md`

## 手順

### 1. 送付先と作る文面を決める
- 引数に `候補2` / `候補3` があれば、その候補を送付先にする: `企業名` `WebサイトURL` `問い合わせ先` `SNS` をその候補の会社の情報に差し替える（公式サイトを WebFetch して問い合わせ先と営業 NG 表記を確認）。research に「送付先を候補N に変更」と追記。
- 人がスプレッドシートで `企業名` を別の候補に書き換えていた場合も同じ扱い。
- 作る文面: プラットフォーム案件（ランサーズ・クラウドワークス・発注ナビ・その他マッチング）は **直接連絡用とプラットフォーム応募用の両方**。Web検索・SNS・紹介は直接連絡用だけ。チャネル指定があればそれを優先。
- 名義は `<C>/outreach.md` §1。`【要確認】` のままなら「クライアント名義」で書き、報告でそう伝える。

### 2. 材料を揃える（書く前に箇条書き）
- 直接連絡用のフック: 送付先企業の**公開情報**から拾った固有の観察（具体的な商品・投稿・ページ・ニュース）
- プラットフォーム用の要点: 募集要件（範囲・納期・金額・体制・質問事項）への回答
- 課題の言い方（直接用は公開情報から推測できる範囲、プラットフォーム用は募集文の言葉を使ってよい）
- 推奨サービス（主 → 副）と `outreach.md` §4 の「最初に起きること」、価格・範囲・注記（`offering.md` そのまま）
- 実績 1 つ（相手の業種に近い方）、CTA 1 つ、文体設定（research §5 → `outreach_rules.md` §4）

### 3. 書く
- **提案文_直接**: `outreach_rules.md` §0 の骨格＋§1 のルール。主チャネル（問い合わせ先がフォーム → フォーム、メール → メール、SNS のみ → SNS DM）の文字数に合わせる。メール・フォームは件名と、署名＋法令表記（【】は空欄のまま）を付ける。
  - 掲載情報にしかない内容（予算・締切・募集文の引用・プラットフォーム名・案件 URL）は書かない。
- **提案文_プラットフォーム**: `outreach_rules.md` §0 の骨格＋§2 のルール。冒頭 5 行で要件に回答、質問には全部答える。特定した企業名は書かない。外部連絡先への誘導は書かない。発注ナビは範囲・金額・納期の表を入れる。
- **2 通目の骨子**: 「詳しく聞きたい」「予算が合わない」「今は不要」に各 1〜2 行（proposals ファイルにだけ書く）。
- 文体のミラーリングは相手の 7 割まで。品位（短文・断定しない・貶さない）は保つ。

### 4. 自己チェック（保存前に必ず）
- [ ] 直接用の冒頭 2 行に、公開情報からの固有の観察がある
- [ ] 直接用に、予算・締切・募集文の引用・プラットフォーム名・案件 URL が入っていない
- [ ] プラットフォーム用の冒頭 5 行で要件に答え、質問に全部答えている。企業名・外部連絡先が入っていない
- [ ] 価格・範囲・注記・実績が `offering.md` と一致。`offering.md` §6 の NG 表現が無い
- [ ] 文字数がチャネルの範囲内（数える）
- [ ] 名義が明確。メール・フォームは署名＋法令表記あり

### 5. 保存・更新
- `<C>/proposals/<id>_<slug>.md` に `sales/_templates/proposal.md` の構成で保存（slug は research と同じ）。
- 本文を scratchpad のテキストファイルに書き出し、まとめて反映:
  `T update <id> 件名=… 提案文_直接=@file:<直接用.txt> 提案文_プラットフォーム=@file:<PF用.txt> 提案文ファイル=sales/clients/<slug>/proposals/<id>_<slug>.md ステータス=提案作成済 次アクション=送付`
  （候補を変えた場合は `企業名` `WebサイトURL` `問い合わせ先` `SNS` `接触チャネル` も同じ update に含める。確度 50% 未満の候補なら `次アクション=候補の確認（確度 xx%）`）
- 単独で呼ばれた時は、最後に `/sales-list` の「共有先を更新」を実行する（`/sales-intake` から呼ばれた時はそちらでまとめて行う）。

### 6. 報告
- 直接連絡用の本文を全文、プラットフォーム用は冒頭 5 行だけ示す。
- 「変えた理由（文体・切り口）」を 3 行以内、「送る前に人が埋める箇所」（署名・名義・【】）と「人が確認すべき点」（確度・営業 NG）を列挙。

## 禁止事項
- `offering.md` に無い価格・実績・サービス範囲。相手の現状を否定する表現。
- 直接用に掲載情報にしかない内容を入れること。プラットフォーム用に外部連絡先や直接取引の誘導を入れること。
- 署名・法令表記のプレースホルダーを勝手に埋めること。名義を曖昧にすること。事実と違う連絡理由を書くこと。
